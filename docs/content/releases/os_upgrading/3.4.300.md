## The `endpoint` field of `/api/v2/endpoint_status/`

With Locations enabled, the `endpoint` field of `/api/v2/endpoint_status/` now carries the `id` that
`/api/v2/endpoints/` lists for the Finding's Asset, the same ID the `?endpoint=` filter takes. It
used to carry the Location's ID, which only matched `/api/v2/endpoints/` when the two IDs happened
to be equal. The Location's ID is still in `location_id`.

`?endpoint=<id>` now returns only the statuses of Findings on that Endpoint's Asset. It used to
include Findings on other Assets that share the same URL.

### What you need to do

If a script reads `endpoint` from `/api/v2/endpoint_status/` and looks the value up as a Location,
read `location_id` instead. A script that passes it to `/api/v2/endpoints/<id>/` now gets the right
row.

## New setting: `DD_GITHUB_STAR_PROMPT_ENABLED`

This release adds a small "Enjoying DefectDojo?" card in the bottom-right corner that asks users to
star DefectDojo on GitHub. It only appears for users whose account is at least 7 days old. Clicking
**Star on GitHub** opens the repository in a new tab and hides the prompt for that user for good;
**Later** or the close button hides it for 30 days. The choice is stored per user.

The prompt is on by default. Set `DD_GITHUB_STAR_PROMPT_ENABLED=False` to turn it off for everyone.

## Deprecation: GitHub issue integration

The **GitHub issue integration** is deprecated and will be removed in **DefectDojo 3.6.0 (December 2026)**. It pushes Findings to GitHub as issues through a GitHub Configuration (a personal access token) and a per-Product repository setting.

The following are affected:

- **UI:** the GitHub Configuration pages (**Configuration > GitHub**), the GitHub repository setting on the Product form, and the **Push to GitHub** option on the Finding form.
- **Setting:** **Enable GITHUB integration** (`enable_github`) in System Settings.
- **Webhook:** the `/github-webhook` route, which accepts requests and does nothing with them.

Each GitHub Configuration page now shows this notice.

### What you need to do

If you push Findings to GitHub this way, plan to move to another issue tracker integration before 3.6.0. In DefectDojo Pro, GitHub is available as a Downstream Connector, which adds each issue to a GitHub Project. Existing GitHub issues are not changed or closed by the removal; DefectDojo stops updating them.

For more information, check the [Release Notes](https://github.com/DefectDojo/django-DefectDojo/releases/tag/3.4.300).
