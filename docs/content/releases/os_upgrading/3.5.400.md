## Lower default limits on zip uploads

DefectDojo checks a zip report before it reads it: how many files it holds, how large each is once uncompressed,
their combined uncompressed size, and how far each one is compressed. Two defaults are lower in this release:

| Setting | Before | Now |
|---|---|---|
| `DD_MAX_ZIP_MEMBER_SIZE` (one file inside the zip, uncompressed) | 512 MB | 128 MB |
| `DD_MAX_ZIP_TOTAL_SIZE` (all files inside the zip, uncompressed) | 1 GB | 128 MB |

`DD_MAX_ZIP_MEMBERS` (1000) and `DD_MAX_ZIP_RATIO` (100) are unchanged.

A zip over a limit is refused with a message naming the limit, as before.

### What you need to do

Usually nothing. If you import zip reports that are larger than 128 MB once uncompressed, set the two
environment variables to the sizes you need, in bytes. For example, to keep the previous limits:

```
DD_MAX_ZIP_MEMBER_SIZE=536870912
DD_MAX_ZIP_TOTAL_SIZE=1073741824
```

## Unknown query parameters on API lists are refused

An `/api/v2/` list used to ignore a query parameter it does not know. A misspelt filter
(`?severty=Critical`) or a parameter the list never had (`?not_a_filter=x`) answered `200` with every
row, so a script that mistyped a filter acted on far more data than intended. Lists now answer `400`
and name each unknown parameter:

```
GET /api/v2/findings/?severty=Critical

400 Bad Request
{"severty": ["Unknown query parameter. It is not a filter on this list."], "message": "..."}
```

A parameter is accepted when the list declares it as a filter, including its lookup variants
(`title__icontains`, `id__in`) and the two halves of a range filter (`epss_score_min`,
`epss_score_max`), or when it is one of the parameters every list takes: `limit`, `offset`, `o`,
`ordering`, `prefetch`, `related_fields`, `response_fields` and `format`. A list's `search` parameter,
where it has one, is accepted too. The filters a list declares are in its OpenAPI schema
(`/api/v2/oa3/swagger-ui/`). Retrieving one object (`/api/v2/findings/1/`) is not checked, and
`/api/v3/` already refused unknown parameters and is unchanged.

### What you need to do

Check that your API clients send only parameters the lists declare. If a client you cannot change
yet sends extra parameters, set `DD_API_UNKNOWN_QUERY_PARAMS`:

| Value | Behaviour |
|---|---|
| `enforce` (the default) | Answer `400`, naming the unknown parameters. |
| `warn` | Serve the request as before (unknown parameters are ignored), name them in the `X-DefectDojo-Unknown-Query-Params` response header, and log a warning. |
| `off` | Ignore unknown parameters, as earlier releases did. |

`warn` is a way to find the clients that send them before you switch back to `enforce`.

For more information, check the [Release Notes](https://github.com/DefectDojo/django-DefectDojo/releases/tag/3.5.400).
