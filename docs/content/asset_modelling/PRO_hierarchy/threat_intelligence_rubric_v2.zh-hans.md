> **尚未提供。** 本页介绍的是一项正在开发中的功能。它不会出现在 **Feature Flags** 页面上,目前也无法开启,无论是在 DefectDojo Cloud 上还是在自托管实例上。目前,每个发现项仍按照[威胁情报](../threat_intelligence/)中所述的方式评分。

[威胁情报](../threat_intelligence/#这如何改变评分方式)会把利用证据转换为 EPSS 量表上的**下限值**:发现项的外部评分至少等于其最强证据所达到的下限。这些下限组成的表称为**评分规则**(rubric)。Rubric v2 是它的下一个版本。它保留每个下限的数值,并新增一种证据:**经 DefectDojo 分析师审核并确认的利用声明**。

## 变化内容

| 证据 | 优先级下限(EPSS 等效值) |
|---|---|
| 已确认的利用证据,**并且**其背后有一个已确认、已命名的威胁行为者(新增) | 45% |
| 位于 CISA KEV **且**用于勒索软件 | 30% |
| 位于 KEV、在野外被利用,或存在**任何已确认的利用证据**,包括已确认的诱饵(canary)观测(新增) | 20% |
| 武器化的公开利用工具(Metasploit / Exploit-DB) | 15% |
| 存在 Nuclei 检测模板 | 12% |
| 仅存在公开概念验证 | 8% |
| 无利用证据 | 无变化 |

各下限的数值与现在相同,发现项的外部评分仍取其 EPSS 推导值与其最高下限中的较大者,因此评分规则只会提高评分。

实际效果如下:

- **更多发现项会达到“已知利用”下限。** 某个 CVE 即使不在 CISA KEV 中,只要有经过审核的利用证据(事件报告、明确说明遭到利用的厂商公告、蜜罐或诱饵观测),就会获得与 KEV 条目相同的 20% 下限。
- **最高下限变得可以达到。** 在 Rubric v1 中,45% 下限需要情报源并不包含的厂商遥测数据,因此从未有发现项达到过它。在 Rubric v2 中,只有当已确认的证据背后有一个已确认、已命名的威胁行为者时,才能达到这一下限,其他情况都不行。
- **不会有任何项目变弱。** 没有经过审核的证据时,漏洞的评分与现在完全相同。带有勒索软件使用记录的 KEV 条目仍保持在 30%:CISA 的勒索软件标记并未指明任何行为者。

**不会**提高下限的内容:未经审核或已被驳回的声明、单独的概念验证,以及扫描器或厂商的“存在利用工具”标记(这些内容会像现在一样显示,但不计为证据)。

## 开启之前

将实例切换到 Rubric v2 可能会提高发现项的优先级,因此 DefectDojo 会在切换之前先评估其影响:针对每个实例,统计有多少发现项会从哪个下限移到哪个下限,并针对每种变化列出涉及发现项最多的漏洞。在 Rubric v2 发布之前,您当前的优先级仍按 Rubric v1 计算。
