> **まだ利用できません:** センサーテレメトリの共有は、DefectDojo Cloudでもセルフホストのインスタンスでも、設定にかかわらず、まだ有効にすることはできません。このページでは、リリース後にどのように動作するかを説明しています。

センサーテレメトリの共有を使うと、インスタンスは匿名化された**センサーのヒットイベント**をDefectDojoの脅威インテリジェンスサービスに送信できます。ヒットとは、ホスト上のセンサーによる1件の検知のうち、CVEに結び付いたものです。共有されたヒットは、どの脆弱性が実際に悪用されているかをインテリジェンスサービスに伝え、その証跡は脅威インテリジェンスのフィードを通じてすべてのインスタンスに届きます。

共有は**DefectDojo Pro**の機能です。**デフォルトではオフ**になっており、スーパーユーザーが有効にするまで何も送信されません。

## 共有されるもの、共有されないもの

各イベントには4つの値だけが含まれ、それ以外は含まれません。

| フィールド | 内容 |
| --- | --- |
| CVE | 一致した検知ルールに付けられているCVE |
| 時刻 | ヒットが確認された時間帯(UTC、1時間単位)。分と秒は送信されません |
| 送信元 | ヒットの発生元の国とネットワーク(ASN)まで。空のことも多い |
| コントリビューターID | 暦月ごとに変わるランダムな識別子 |

イベントには、ペイロードやリクエストボディ、ホスト名、IPアドレス、ユーザー名、コマンドライン、アセット名、会社名、検知ルールの名前や識別子、インスタンスの名前やURLは一切含まれません。送信元は、インスタンスが送信元を調べるよう設定されている場合に限り、かつパブリックアドレスについてのみ記入されます。その場合、DefectDojoはインスタンス上で国とネットワークを割り出し、何かを送信する前にその場でアドレスを破棄します。

ルールの識別子は意図的に除外されています。自分で作成したルールには、自社名、ホスト名、個人名など、どのような名前でも付けられるためです。

イベントはインスタンスのライセンスキーとともにDefectDojoに配信され、インテリジェンスサービスはそれによってイベントを受け付けます。キーは配信に添えて送られ、イベントの中には含まれません。

コントリビューターIDにより、インテリジェンスサービスは1か月の間にいくつの異なるインスタンスが同じCVEを確認したかを数えることができます。IDはランダムに生成され、毎月新しいものに置き換えられ、新しいIDから古いIDを割り出すことはできません。

送信されるのは、共有を有効にした後のヒットのうち、直近24時間以内のものだけです。共有をオフにすると、送信待ちのイベントはすべて削除され、コントリビューターIDも破棄されます。契約条項が変更された場合も同様です。共有を再び有効にすると、新しいコントリビューターIDで始まります。

## 有効にする前に

共有は、DefectDojoとの契約内の条項によって規定されます。カードには、共有を有効にすることで同意する**契約条項のバージョン**が表示され、そのバージョンがインスタンスで利用可能になるまで共有を有効にすることはできません。

契約条項は、共有が利用可能になる前に公開されます。

DefectDojoが後から条項の新しいバージョンを公開すると、共有は自動的に一時停止します。カードにその旨が表示され、旧バージョンのもとで送信待ちだったイベントは削除され、スーパーユーザーが新しいバージョンのもとで共有を再び有効にするまで何も送信されません。一時停止中はチェックボックスが外れた状態で表示されるため、新しいバージョンに同意するには改めてチェックする必要があります。その後、共有は新しいコントリビューターIDで最初からやり直されます。

エアギャップ環境のインスタンス、公開デモ、サンドボックスでは、共有は利用できません。

## 共有をオンまたはオフにする

1. スーパーユーザーとしてサインインし、**Settings > System Settings**を開きます。
2. ページ下部にある**Sensor Telemetry**カードまでスクロールします。
3. 共有される内容と、カードに表示されている契約条項のバージョンを確認します。インスタンスに条項のアドレスが設定されている場合、カードのバージョンの横にそのリンク(**Read the contract term**)が表示されます。
4. **Share Sensor Hit Events**を選択し、**Submit**を選択します。停止するには、チェックボックスを外して**Submit**を選択します。

すべての変更は、変更したユーザーとともに監査ログに記録されます。

## カードに表示される内容

* **Sharing**: Off、On、Paused(契約条項が変更された)、On, Not Sending(インテリジェンスのエンドポイントまたはライセンスキーが設定されていない。どちらが欠けているかはカードに表示されます)、Not Availableのいずれか。
* **Events Shared**、**Events Waiting**、**Events Dropped**: 配信済み、キュー内、破棄済みのイベントの数。配信できないイベントは最長1日再試行され、その後破棄されます。
* **Last Shared**: 最後にイベントが配信された日時。
* **CVEリスト**: センサーが観測したCVE(最近確認された最大200件)と、それぞれのヒット数、共有された数、初回と最終の確認日時。カードのタイトルには、観測されたCVEの総数が表示されます。このリストは、共有がオンかどうかにかかわらずインスタンス上に保持されます。
* **Seen Elsewhere**: 共有している他のインスタンスが同じCVEを確認したかどうか。共有がオンでインテリジェンスサービスが応答している間だけ、かつインスタンスがすでに共有したCVEについてのみ表示されます。問い合わせにはCVEが含まれるため、共有を有効にする前にしか確認されていないCVEが問い合わされることはありません。それ以外の場合は、表の下の行に空欄の理由(たとえば、インスタンスにインテリジェンスのエンドポイントやライセンスキーが設定されていないこと)が表示されます。

カードは、インスタンスにセンサーがある場合、CVEを観測した場合、または共有のための設定が行われた場合に表示されます。

## セルフホスト環境での設定

セルフホストのインスタンスでは、運用担当者が次の環境変数を設定します。すべてデフォルトでは空で、空はオフを意味します。

| 変数 | 用途 |
| --- | --- |
| `DD_SENSOR_TELEMETRY_CONTRACT_TERM_VERSION` | 契約条項のバージョン。これがないと共有を有効にできません |
| `DD_SENSOR_TELEMETRY_CONTRACT_TERM_URL` | 任意。契約条項を読めるHTTPSアドレス。カードのバージョンの横にリンクが表示されます |
| `DD_SENSOR_TELEMETRY_ENDPOINT` | インテリジェンスサービスのHTTPSベースURL。これがないと、ネットワーク呼び出しは一切行われません |
| `DD_THREAT_INTEL_LICENSE_KEY` | 配信ごとに送信されるライセンスキー。これがないと、ネットワーク呼び出しは行われません |
| `DD_SENSOR_TELEMETRY_SOURCE_RESOLVER` | 任意。パブリックな送信元アドレスを国とASNに変換する関数の、ドット区切りのPythonパス。DefectDojoには国やASNのデータベースが含まれていないため、これがないとイベントに送信元は含まれません |
