Knowledge Check (Pro)

Twenty questions about what Import and Reimport are for in DefectDojo Pro, and how they create, match, close and reopen Findings.

Pick an answer to see whether it’s right and why. Your first pick is the one that counts toward your score, but you can then pick the other options to see where each one would point you. Each explanation links to the page that covers it. Nothing is recorded: your answers stay in your browser and disappear when you leave the page.

1.What happens when you import a scan file into DefectDojo?
The import creates a new Test nested under an Engagement, with one Finding per vulnerability. The Test is named after the scan type. Read more

Where to look instead: DefectDojo doesn’t scan. To pull results from your tools automatically, connect them with Upstream Connectors. Upstream Connectors →

Where to look instead: Findings are created automatically. If your tool’s format isn’t supported, the Universal Parser can map it. Universal Parser →

Where to look instead: To bundle related Findings together, use the Group By option on import to create Finding Groups. Import options: Group By →

2.What is Reimport for?
Reimport doesn’t replace a Test’s data. It compares the incoming file with what’s there, then creates, leaves untouched, closes or reopens Findings. Read more

Where to look instead: Reimport compares rather than replaces. To keep each scan as its own Test, use Import instead. Import vs. reimport endpoints →

Where to look instead: To fix Findings directly, edit them, or change many at once with bulk edit. Editing Findings →

Where to look instead: To get Findings out of DefectDojo, DefectDojo-CLI exports them to JSON or CSV. DefectDojo-CLI export →

3.When would you call the API’s /import endpoint instead of /reimport?
/reimport handles almost everything, including the first upload. /import suits a pipeline that keeps every run as a separate Test. Read more

Where to look instead: /reimport can create the Test itself, along with its Engagement, Asset and Organization, when Auto Create Context is on. Import vs. reimport endpoints →

Where to look instead: For large files, keep Process Findings Asynchronously on so the work runs in the background. Process Findings Asynchronously →

Where to look instead: Both endpoints can close old Findings. Import can also close them across the whole Asset. Close Old Findings →

4.Your team wants scan results to land in DefectDojo without anyone uploading files by hand. Which of these could do that?
Besides the UI, scans can come in through the API, Universal Importer and DefectDojo-CLI, Connectors, and Smart Upload. Read more

Where to look instead: The form is manual. To script uploads from CI or a scheduled job, use Universal Importer or DefectDojo-CLI. Universal Importer & DefectDojo-CLI →

Where to look instead: There’s no email import. A CI job calling the API’s /reimport endpoint does the same job. Import from API →

Where to look instead: That one applies tags and custom fields to endpoints from a CSV, not scan results. Endpoint Meta Importer →

5.What is Smart Upload for?
Smart Upload routes Findings from infrastructure scans (Nexpose, NMap, OpenVas, Qualys, Tenable) to Assets by host, once a host has been assigned. Read more

Where to look instead: To upload many files from a script, use Universal Importer or DefectDojo-CLI. Universal Importer & DefectDojo-CLI →

Where to look instead: You still pick the scan type. For a format with no parser, map it with the Universal Parser. Universal Parser →

Where to look instead: Deduplication isn’t skipped, but you can choose whether an import waits for it with the deduplication execution mode. Deduplication execution mode →

6.What does a Test’s Import History show?
Each import or reimport is one row, with a timestamp, any build, branch, commit and version details, and the created, closed, left untouched and reactivated counts. Read more

Where to look instead: For a record of who did what, use Audit Logs. Audit Logs →

Where to look instead: Import History records changes, not snapshots. For a record of how objects changed, use Audit Logs. Audit Logs →

Where to look instead: Import History doesn’t keep files. To get Findings out, use DefectDojo-CLI’s export. DefectDojo-CLI export →

7.What is the Do Not Reactivate option for?
Triage-less scanners such as tfsec flag everything on every run. Do Not Reactivate stops each import from reopening Findings you’ve already closed. Read more

Where to look instead: Risk-accepted Findings already stay inactive on reimport. Manage them with Risk Acceptance. Risk Acceptance →

Where to look instead: Imports go wherever they’re sent. To pause a Connector’s automatic syncs, manage its operations. Connector operations →

Where to look instead: Duplicates are handled by Deduplication, which you can tune per tool. Deduplication Tuning →

8.Do you need to create the Organization, Asset and Engagement before importing?
Every upload method can create the hierarchy at import time. In the Add Findings form, just type the names of the Organization, Asset or Engagement you want created. Read more

Where to look instead: The Add Findings form can create them as you fill it in, and the API’s Auto Create Context option does the same. Add Findings form options →

Where to look instead: The hierarchy can be reorganized whenever you need. You can reorganize later →

Where to look instead: To send Findings to the right Asset automatically, use Smart Upload. Smart Upload →

9.You reimport a file that contains a vulnerability already open as a Finding in the Test. What happens?
Matches are discarded rather than recorded as duplicates, and the Test page shows them as Left Untouched. Read more

Where to look instead: That’s what Same-Tool Deduplication does across separate Tests. How duplicates work →

Where to look instead: Only fix_available and fix_version are updated. To change other fields, edit the Finding. Editing Findings →

Where to look instead: Reimport never fails on a match. Check what it did in Import History. Import History →

10.Through the API, you reimport a file that no longer contains one of the Test’s open Findings, without setting close_old_findings. What happens to that Finding?
On the reimport endpoint close_old_findings is true by default, so Findings missing from the file are closed and shown as Closed. Read more

Where to look instead: To keep Findings open on reimport, set close_old_findings to false. Close Findings →

Where to look instead: Reimport never deletes Findings. To remove duplicates automatically, see Delete Deduplicate Findings. Delete Deduplicate Findings →

Where to look instead: To mark matching Findings as false positives automatically, use False Positive History. False Positive History →

11.A Finding was closed, and the vulnerability shows up again in the next reimport. What happens by default?
Reimport assumes the vulnerability came back despite the fix, reopens it, and counts it as Reactivated. Read more

Where to look instead: To keep closed Findings closed, turn on Do Not Reactivate. Reopen Findings →

Where to look instead: New Tests per run only happen with /import. Import vs. reimport endpoints →

Where to look instead: To ignore a recurring issue on purpose, accept the risk or mark it a false positive. Risk Acceptance →

12.You reimport with Force Active on. One matched Finding is Risk Accepted. What happens to it?
Force Active reopens mitigated Findings but never overrides an explicit decision: Risk Accepted, Duplicate, False Positive or Out of Scope. Read more

Where to look instead: Removing the Risk Acceptance is your call. Do that first, and the Finding can then be reactivated. Risk Acceptance →

Where to look instead: Explicit triage decisions win over Force Active. The full list of statuses it won’t override is in the reimport guide. Force Active behavior →

Where to look instead: Closing only applies to Findings missing from the file. Close Findings →

13.You reimport into Test A with Close Old Findings on. A Finding missing from the file exists only in Test B, in the same Engagement. What happens to it?
Unlike Import, Reimport never looks at other Tests when deciding what to close. Read more

Where to look instead: That’s Import’s scope. To close across the Engagement, use Import with Close Old Findings. Close Old Findings →

Where to look instead: Duplicates come from Deduplication, which runs on the Findings a reimport creates. Reimport Deduplication →

Where to look instead: Scan type matters for Import’s closing scope, which Close Old Findings Within This Asset widens to the whole Asset. Close scope: Engagement vs. Asset →

14.Close Old Findings is on. A Finding missing from the file has a different service value from the one set on this import. Is it closed?
Close Old Findings respects the service field, so separate services in one Test don’t close each other’s Findings. Read more

Where to look instead: Service matters to deduplication too, since it can change a Finding’s hash. Service field and its impact →

Where to look instead: For age-based closing, a Triage Engine rule can match on older_than_days. Triage Engine conditions →

Where to look instead: Force Active is about reopening matched Findings, not closing missing ones. Force Active behavior →

15.What does Close Old Findings Within This Asset change?
close_old_findings_product_scope widens Import’s closing to the whole Asset. It needs close_old_findings and has no effect on reimport. Read more

Where to look instead: It still only matches the same scan type. To close Findings by other criteria, use a Triage Engine rule. Triage Engine →

Where to look instead: It needs Close Old Findings on as well; on its own it has no effect. Close scope: Engagement vs. Asset →

Where to look instead: Reimport is always limited to its Test. To consolidate runs, reimport them into one Test. Reimport →

16.The report sets its own dates, and you also set Scan Date when importing. Which date do the Findings get?
A Scan Date set at import always wins. Without one, the report’s date is used, and failing that, the import date. Read more

Where to look instead: To keep the report’s dates, leave Scan Date empty. Scan Date →

Where to look instead: That’s only when neither the report nor Scan Date sets one. Scan Date →

Where to look instead: Finding dates matter because SLAs are calculated from them. Priority, Risk and SLAs →

17.You want to upload a file of a different scan type to an existing Test. What do you do?
The Re-Import form won’t let you change the scan type or destination. For either, use the Add Findings form. Read more

Where to look instead: The reimport form can’t change the scan type or destination. The reimport form →

Where to look instead: Engagements hold Tests from many tools, so import the new type into the same Engagement. Add Findings form →

Where to look instead: Reimport never converts a Test. With Auto Create Context it creates a new one instead. Import vs. reimport endpoints →

18.After every reimport, Findings are closed and recreated just because a line number moved. What fixes this?
Reimport matching uses its own deduplication settings. Location Drift Matching recognizes a moved Finding as the same one. Read more

Where to look instead: That stops closed Findings from reopening; it doesn’t change how matches are found. Reopen Findings →

Where to look instead: To clean up duplicates automatically, use Delete Deduplicate Findings. Delete Deduplicate Findings →

Where to look instead: Separate Tests rely on Same-Tool Deduplication instead, which you can tune per tool. Deduplication Tuning →

19.You import with Minimum Severity set to High. What happens to the Medium vulnerabilities in the file?
Anything below the minimum severity is ignored and never becomes a Finding. Read more

Where to look instead: To import everything but control its status, use the Active option instead. Import options →

Where to look instead: To change severities automatically, use a Set Severity node in a Triage Engine rule. Set Severity node →

Where to look instead: To group Findings, use Group By on import to create Finding Groups. Import options: Group By →

20.Through the API, you import with Process Findings Asynchronously turned off. When does the API respond?
With asynchronous processing off, DefectDojo doesn’t return a successful response until every Finding exists. Read more

Where to look instead: That’s the default, with the option on. Process Findings Asynchronously →

Where to look instead: To wait for deduplication too, set deduplication_execution_mode to async_wait or sync. Deduplication execution mode →

Where to look instead: Both settings work through the API; asynchronous is just the default. Process Findings Asynchronously →
