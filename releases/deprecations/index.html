Deprecations

On this page
  • Deprecated (scheduled)
  • Planned, no timeline yet
  • Removed
    • 3.x releases
    • Removal release not recorded
    • 2.x and earlier

This page lists what has been removed from DefectDojo and DefectDojo Pro, what is deprecated and scheduled for removal, and what is planned for removal without a release yet. It covers open source and Pro.

A deprecated feature keeps working until the release that removes it. Where it can, DefectDojo warns you in the product: deprecated pages show a warning banner, deprecated API endpoints send an X-Deprecated header, and the Pro sidebar marks deprecated pages with a DEPRECATED or LEGACY badge (see Menu Badges).

DefectDojo Pro is built on the open source release with the same version number, so when open source deprecates or removes a feature, Pro deprecates or removes it in the same release. The exceptions are features that Pro keeps or replaces with its own version, and those rows say so. The Affects column shows who each row applies to: Open Source and Pro, Open Source only (Pro keeps its own version), or Pro only. Where a version was never published, the table says Not recorded.

For each release’s details, see the Pro Changelog and the Open Source upgrade notes.

2.x and earlier#

Removals in 2.x and earlier releases, such as MySQL and RabbitMQ support, asynchronous import, django-auditlog and the Finding cve field, are listed in the Open Source upgrade notes for each release. The same rule applies to them. One exception: open source removed asynchronous import in 2.47, and Pro import and reimport have their own background_import option.
